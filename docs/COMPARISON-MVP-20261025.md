# A/B案と相談用PDF

2026-10-25。既存の複数シート、メモ、通路幅、席数集計、Fabric合成とjsPDFを再利用する。新しい外部サービスや依存は追加しない。

## 使い方と保存

図面を開き「同じ図面から A/B 案を作る」。元シートを残し、図面・縮尺・配置・既存メモ・計測線を独立した2シートへコピーする。B案が開くので編集し、シート一覧からA案へ切り替えられる。
「並べて比較・相談用PDF」で組を選ぶ。画面は2案を横並びに表示し、既存の集計関数による席数目安、縮尺の校正状態、通路幅、メモを付ける。
相談用PDFはA4横の比較図と、通路幅・メモの記録ページをローカル生成する。長文はページを追加し、日本語はcanvasで画像化する。PDF内の文字は検索・選択できない。固定の印刷縮尺は保証せず、用紙に収めた比較であることを明示する。
面積・席数・通路幅は法令適合や安全の保証にしない。最終確認先を毎ページと比較画面に表示する。

既存JSONの構造は維持し、シートに任意の `comparisonGroup`、`comparisonVariant`、`measures` を追加。読込時は計測線の有限数を検証する。旧JSONはこれら無しで読める。旧アプリに読み戻すと追加情報は保持されないため、新機能を使ったJSONは現版で扱う。
メモを新規作成・編集するProゲートは維持。A/B作成・比較・相談PDFのために既存機能の課金区分は変更しない。元シートと各案の編集履歴は独立する。A/Bの作成自体はシートの追加であり既存の配置Undoの対象外。不要な案は既存のシート削除を使う。
容量を超えた自動保存失敗は既存の警告・JSON保存へ案内する。図面のコピー数が増えるため大きな図面はJSONで保存する。

## 大型版：変更什器の差分・明細

1. 什器に安定した `fixtureId` を追加し、A/B作成時はIDと原案revisionを保持する。旧データへのID付与はプロジェクト内で1回だけ行う。形状や名前の近似で同一物と決めない。
2. 同じ図面・元revision間で追加／削除／移動／回転／寸法／型番の差分を計算。移動や寸法の許容誤差はmmで定義し、縮尺の違いは別の確認事項にする。席数は既存集計関数を使う。
3. 単価・数量・備考は利用者入力の任意欄とし、未入力を0円と推測しない。通貨・税・見積条件を分ける。製品から施工見積の正確性を保証しない。
4. JSONに基準版と差分を保存し、旧データ読込、ID衝突、複製什器、削除と再追加、欠損revision、単位違い、中断、出力改ページをfixtureで検証する。

依存条件：什器IDの寿命、Undo/複製/JSON読込時のID規則、変更の許容誤差、明細の税・契約上の位置づけを確定する。クラウド共同編集、権限管理、中止済みiOS開発は含まない。契約・セキュリティ上の曖昧な判断は保留。
