# 個人情報の漏えい等が起きたときの手順（MiseFits / MenuFits / 全銀ポン 共通）

作成: 2026-09-25。サイトには配信しない（`_config.yml` で除外）。リポジトリは公開なので、秘密情報は書かない。

## 何が「個人情報」にあたるか

アプリの図面・レイアウトはブラウザ内だけで処理し、サーバーに送らない。サーバー側（Firebase・米国）にあるのは購入関係だけ：
購入者のメールアドレス、請求先の国、Stripe の決済ID、ライセンスキー、端末ID（ランダム）。カード情報は持たない（Stripe / Link が保持）。

## 気づいたら（最初の24時間）

1. **止める**：原因の鍵・パスワードを失効させる（`firebase functions:secrets:set` で差し替え→対象関数だけデプロイ、
   Stripe の鍵はダッシュボードでロール）。必要なら Firestore のルールはすでに全面拒否なので、関数を一時停止する。
2. **記録する**：いつ・何が・何件・誰の分か。Firestore の該当コレクション、関数のログ（`firebase functions:log`）を保存。
3. **影響を見積もる**：メールアドレスが漏れたのか、キーだけか。キーだけなら該当キーに `revoked: true` を付けて再発行で足りる。

## 届出・通知の期限（目安。最終判断は専門家に）

| 法令 | 対象 | 期限 |
|---|---|---|
| 日本 個人情報保護法 | 要配慮情報・不正アクセス・財産的被害のおそれ・1,000人超など | 個人情報保護委員会へ**速報（3〜5日以内）**、確報（30日以内）＋本人通知 |
| シンガポール PDPA | 重大な被害のおそれ、または500人以上 | 評価後 **3暦日以内**に PDPC、本人にも |
| ニュージーランド Privacy Act 2020 | 深刻な被害のおそれ | **できるだけ早く** OPC と本人 |
| オーストラリア | 小規模事業者の除外の対象（年商 A$3m 以下）だが、任意でも本人通知を検討 | — |
| EU/英国 | いまは販売していない | （販売開始時に 72 時間ルールを追記） |
